Someone else holds the money

  • GitHub Sponsors — the platform holds it, then pays you.
  • OpenSats, Brink, Spiral — a board sits on a treasury.
  • Geyser — a campaign page, not a public address in git.

They can freeze it, redirect it, or sit on it. That is a queue. It is not escrow.

What we believe

Mainnet design. Signet is still one operator key.

Nobody holds the keys
Project funds sit in public Bitcoin escrow. Plebly cannot freeze, redirect, or take them. Five keyholders sign. The org holds none.
The record is public
Proposals live in Plebly/proposals. Anyone can fork it. GitHub is not the last copy.
Rules over discretion
Fees and payout rules are published in git. Changes happen in the open.

How it works

  1. Propose. Name the problem. Say what done looks like.
  2. Donate. Send Bitcoin to the project’s public address. No account.
  3. Build. Hit the floor. A builder applies. A small bond holds the place.
  4. Pay. Reviewers check the work. Payment goes out monthly.

Lightning lands in that same address on mainnet. Unpaid invoices do not count. Floor: 100,000 sats mainnet · 10,000 sats signet.

What Plebly cannot do

The site

  • Hosts the app
  • Opens PRs into git
  • Checks fees and balances
  • Tracks claims and windows

Not the site

  • No production spending key
  • No signed releases from Workers
  • No erasing the git record
  • No fee on refunds

Mainnet is 3-of-5. No timelock. Three keyholders can stall. The stall is public. No one holds more than one key. At least two keyholders have no other Plebly role.

Where we are

Live mode: single-key-test. Not production escrow. Not a multisig rehearsal. No real mainnet bounties.

  • Fee address for mainnet — not published
  • Five keyholders — roster empty
  • Five reviewers — live count is zero
  • 10,000 sat submission fee
  • 5% at payout — 3% platform, 2% keyholders, 500,000 sat cap
  • Taken when the work is paid, not when you donate
  • Fee changes: public process, 30-day notice

No users. No TVL. No mainnet volume.
